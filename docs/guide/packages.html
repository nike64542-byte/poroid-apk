Packages & services

The VM is a standard Kali Linux (arm64) system. Install packages with apt as you would on any Debian machine. Changes persist across reboots on the writable ext4 overlay.

Package management with apt

Kali's kali-rolling repository is pre-configured in /etc/apt/sources.list. Any package available for aarch64 can be installed directly. It is a rolling release, so apt upgrade keeps the whole system current.

CommandWhat it does
apt updateRefresh the package index from the repositories
apt upgradeUpgrade all installed packages to the latest versions
apt install <pkg>Install a package (and its dependencies)
apt remove <pkg>Remove a package
apt search <kw>Search for packages by name or description
apt show <pkg>Show details about an installed or available package
Kali documentation

Kali's documentation is the authoritative reference for package management, tools, and system administration. These are the best places to look:

  • Package search: kali.org/tools
  • Kali Docs (installing, configuring, troubleshooting): kali.org/docs

Podman, Docker and LXC are all ready at boot

Rootless Podman needs no daemon and works immediately. The Docker and LXC services are enabled in the default runlevel, so they start automatically on every boot - there is nothing to run. Confirm with rc-status, and use rc-service docker stop if you want to free memory when you are not using it.

OpenRC service management

The VM uses OpenRC as its service manager, driven by sysvinit as PID 1 (/etc/inittab calls OpenRC's sysinit, boot, and default runlevels in order). Standard OpenRC commands work as-is:

# List all services and their status
~# rc-status

# Start, stop, restart, or check a service
~# rc-service ssh start
~# rc-service docker stop
~# rc-service podroid-x11 restart
~# rc-service podroid-x11 status

# Enable a service you installed on every boot (adds to the 'default' runlevel)
~# rc-update add crond default

# Disable a service from auto-starting (e.g. Docker, to save memory)
~# rc-update del docker default

Podroid system services

These OpenRC services are part of Podroid's Kali image. Most start automatically; a few are conditional.

ServiceWhat it does
podroid-bootstrap First service to run. Sets the system clock (AVF path), enables cgroup v2, loads kernel modules, mounts devpts/shm/mqueue and configfs (/sys/kernel/config, needed by targetcli/LIO), configures ZRAM swap, sets sysctl tunables, sets the hostname, and bind-mounts the persistent ext4 storage onto the Podman/Docker/LXC data directories.
podroid-network Brings up eth0 (10.0.2.15/24 on QEMU, DHCP on AVF), adds the default route, and writes /etc/resolv.conf with the device's own resolver first, then 8.8.8.8 / 1.1.1.1.
podroid-resize Runs the terminal resize daemon: reads RESIZE rows cols messages from the ctrl virtio-console (hvc1) and calls stty on hvc0 so the shell prompt redraws correctly after keyboard or orientation changes.
podroid-x11 Starts Xvnc on display :0 (port 5900) and PulseAudio on port 4713. These back the in-app X11 viewer and audio stream.
podroid-vsock AVF only. Starts the vsock port-forwarding agent that bridges Android-side TCP connections to guest vsock ports. On QEMU this service marks itself inactive and does nothing.
podroid-hostd The guest-to-Android bridge daemon (both backends). Listens on a guest-local Unix socket and relays requests from the podroid-notify, podroid-forward, podroid-open, podroid-power, and podroid-server CLIs to the Android app over its control transport (a virtio-console port on QEMU, vsock on AVF), which posts the notification or writes the port-forward rule. See Networking & ports.
podroid-ready Runs last (after all other services). Emits the boot-stage markers (Starting SSH..., Almost ready..., Ready!) that the Android app watches to detect a successful boot. Also sets OOM scores on infrastructure processes so the kernel reaps user apps before killing the VM.
ssh SSH server (OpenSSH) on guest port 22, started at boot. It is reachable from the host and LAN only when the SSH toggle is on (which adds the 9922→22 forward). Default credentials: root / podroid.
docker Docker daemon. Enabled in the default runlevel, so it starts automatically at boot. Stop it (rc-service docker stop) or disable it (rc-update del docker default) to save memory if you only use Podman.
lxc LXC container manager. Also enabled in the default runlevel and starts automatically at boot.
dnsmasq.lxcbr0 DHCP and DNS for the LXC bridge network (lxcbr0). Started alongside the lxc service.
